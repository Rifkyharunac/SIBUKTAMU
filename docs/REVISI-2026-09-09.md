# Perbaikan alur petugas dan respons aplikasi

## Penyebab logout ditolak

Permintaan formulir keluar dari browser membawa `Origin: null` dan
`Sec-Fetch-Site: same-origin` saat kebijakan halaman memakai `no-referrer`.
Pemeriksaan sebelumnya menganggap asal tersebut sebagai situs berbeda.
Perilaku browser ini dijelaskan pada [dokumentasi Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy).

Pemeriksaan sekarang menerima asal kosong/opaque hanya jika metadata browser
menegaskan `same-origin`. Asal asing, `cross-site`, `same-site`, dan permintaan
tanpa bukti asal tetap ditolak. Host dari header penerusan tidak dipercaya.

## Perubahan

- Tombol keluar memakai permintaan JSON, menonaktifkan klik berulang, lalu
  mengganti halaman ke login setelah server mencabut sesi dan menghapus cookie.
- Formulir tanpa JavaScript tetap didukung dengan pengalihan 303. GET tidak
  mengubah sesi. Cookie rusak tidak menyebabkan crash. Kegagalan pencabutan
  sesi ditampilkan sebagai kegagalan, bukan keberhasilan semu.
- Respons kosong, HTML dari gateway, JSON tidak valid, dan jaringan terputus
  ditangani dengan pesan yang dapat dipahami. API admin dengan sesi kedaluwarsa
  mengarahkan kembali ke login.
- Dashboard menunggu konfirmasi penyimpanan, mencegah mutasi bersamaan, dan
  mengabaikan respons pemuatan yang sudah usang.
- Indikator notifikasi memakai status server setelah penandaan terbaca.
  Penandaan ganda ketika berpindah ke halaman notifikasi dihapus.
- Menu Ganti Sandi tersedia untuk petugas yang sudah mengganti sandi awal.
  Halaman penggantian sandi juga menyediakan tombol keluar.
- Pengiriman penilaian memulihkan tombol setelah kegagalan dan menampilkan
  error pada halaman penilaian. Penyelesaian tamu memerlukan respons hasil
  yang valid sebelum menghapus kunjungan tersimpan di perangkat.

## Verifikasi

`node tests/security-integration.cjs` menjalankan handler API sebenarnya
dengan database SQLite dan penyimpanan objek terisolasi. Tidak menggunakan
data tamu produksi dan tidak mengirim WhatsApp sungguhan.

Cakupan: header logout browser, perlindungan asal permintaan, batas ukuran,
respons API rusak/offline, login dan pencabutan sesi, pendaftaran dan token
kunjungan, penyelesaian berulang, PDF/Excel, penandaan lebih dari 100 notifikasi,
master bidang/layanan/pegawai, pengaturan, survei, arsip/penghapusan notifikasi,
pembatasan peran, pembatasan laju, cookie rusak, dan kegagalan penyimpanan logout.

Pemeriksaan tipe dan build produksi dilakukan untuk memastikan integrasi kode.
Pengujian otomatis ini bukan pengujian interaksi browser produksi; pengiriman
WhatsApp nyata tetap memerlukan konfigurasi penyedia yang valid.
